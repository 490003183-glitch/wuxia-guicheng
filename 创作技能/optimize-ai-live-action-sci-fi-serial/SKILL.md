# AI真人科幻连续剧剧本优化

口头别名：`爽剧优化 skill`。用户使用这个简称时，直接执行本Skill，无需要求用户复述正式英文名称。

## 核心原则

始终遵守：客观、全面、科学。

- 把已确认事实、材料内证据、推断、建议和未知分开。
- 默认执行核查，不因用户只说“优化”就重写定稿内容。
- 只有用户明确要求“改写、重写、输出爽剧版”时才改写。
- 正典、信息权限、人物声线、合规和已确认制作边界是硬门禁，不能被爽点分数抵消。
- 爽点包括能力、规则、权力、关系、装备、真相、生存和人格兑现，不等同于打脸或狠话。
- 不用点赞代替播放/完播，不把个别评论当全体观众，不伪造平台算法阈值。

## 开始前必须读取

每次使用先读完整的 [evidence-based-criteria.md](references/evidence-based-criteria.md) 和 [output-schemas.md](references/output-schemas.md)。

根据任务追加：

- 涉及AI生成、Seedance、镜头拆分或上线合规：读 [compliance-and-ai-production.md](references/compliance-and-ai-production.md)。
- 需要确定性预扫描：剧本输入运行 `scripts/audit_screenplay.py`。脚本只产生启发式信号，不能代替正典和人工判断；检测到小说章节时会明确跳过，不得把无效的场景或对白统计写进结论。

## 工作流

### 1. 确认模式和授权边界

将请求归为：

- `audit`：核查、诊断、评估、看看哪里不爽。只报告，不改稿。
- `rewrite`：用户明确要求改写。先核查，再在授权范围内改。
- `compare`：比较两个版本。不得自动合并。
- `production`：把已确认剧本转为可生成的单元。不得借制作拆分改变剧情。

输入资料不完整但仍能继续时，用假设和置信度推进；只有正典冲突、授权缺失或关键选择会改变结果时才停下询问。

### 1.1 先分流输入形态

- `screenplay`：使用完整十维核查；涉及AI真人制作时检查场景、演员、空间、连续性和生成单元，并可运行确定性预扫描。
- `novel`：按连续阅读核查 `E/T/M/P/R/C/S/H/O`；除非用户同时要求影视改编评估，否则将 `G` 标为 `N/A`。以段落、行动节拍、视角注意力和章节状态变化为证据，不用剧本场标题、说话者格式或嘴型统计衡量小说。
- `unknown`：说明识别依据和限制；不得把解析失败后的零场景、低对白数当成作品事实。

### 2. 建立材料状态表

逐项标记：正式设定、定稿剧本、工作稿、原始资料、待确认、制作约束、公开表现。

以用户指定的 CANON_ROOT 为正式来源，OUTPUT_ROOT 为交付位置。只读核查不自动写回主库。

### 3. 先过硬门禁

检查：

1. 正典、时间线、版本/并行关系；
2. 角色信息权限和人物立场；
3. 科幻规则因果与操作上限；
4. 用户是否授权改动定稿内容；
5. AI标识、备案、肖像/声音等合规待核项；
6. 关键镜头是否在当前AI真人工作流中明显不可控。

发现阻断时先列证据与影响。不要继续用创意填补冲突。

### 4. 做十维核查

按 `E/T/M/P/R/C/S/G/H/O` 检查：入口、本集任务、机制行动化、兑现、再入场、人物关系、科幻有效性、AI真人可制作性、结尾钩子、原创性/疲劳。

使用0–3或`N/A`只做问题定位；每个评分必须附材料证据、风险和置信度。不得生成一个可以掩盖硬错误的总分。

当单集或单章包含“首次、公开揭露、不可逆杀人、能力觉醒、关系决裂、身份确认、装备毁损”等不可重复兑现时，追加一次性里程碑账本：

- 本次真正消耗了哪些只能首次发生一次的事件；
- 哪些兑现仍被保留；
- 下一次升级能否换用代价、关系、权限、敌方学习、后果或规则难题，而不是只放大规模；
- 当前高密度是合理的叙事高点，还是把后续连续剧引擎提前透支。

不设固定数量阈值，不因里程碑多就自动降分；把“本章很爽”和“后续更难升级”作为两个并存结论。

### 5. 先列保护项，再提优化

明确哪些内容不能被优化掉：角色的生活质感、关系边界、独特语气、正式世界观、信息权限、已确认动作上限、版本关系和有意的形式实验。

然后按最小改动阶梯提出方案：

1. `L0` 发布/包装：标题、合集顺序、片头卡、花絮/重剪说明。
2. `L1` 重排已有节拍：提前异常、目标、实物或结果，不新增正典。
3. `L2` 行动化说明：用证据、操作、权限、道具、身体或空间后果承载信息。
4. `L3` 局部场景/对白改写：定稿内容需明确授权。
5. `L4` 结构重写：改变场序、视角、集界或重要事件，必须明确授权和影响。

发布标题使用项目已确认的集号、日期和版本，不根据章节编号猜测发布顺序。

### 6. 改写时执行双重护栏

改写前锁定：不得改变项、允许改变项、目标时长、场景/人物/生成限制。

改写后逐项复核：

- 正典、日期、因果、信息权限；
- 人物声线与主动选择；
- 本集任务、状态变化和具体钩子；
- 科幻机制是否被行动验证；
- 生成单元能否明确首帧、主动作和结束态；
- 是否新增了通用狠话、无依据救场、重复反转或专名负担。

### 7. 数据结论必须可证伪

若提供公开表现，只把它用于生成假设，并列出粉丝、投流、发布时间、标题封面、IP、合集、重剪、停更回归和连发分流等混杂项。

有后台数据时，优先使用2秒跳失、5秒留存、25/50/75/100%留存、平均观看时长、完播、关注转化和流量来源。一次测试尽量只改变一个主要变量。

## 确定性预扫描

Python 3.10 或更新版本，仅标准库。命令相对于本技能目录运行；输入文件必填，默认只向标准输出报告，--output 可指定输出文件。

```bash
python3 scripts/audit_screenplay.py /absolute/path/to/script.md --format markdown
```

脚本可提示：超长对白、疑似说明句、重复句式、专名密度、场景/人物负荷、`不是A，而是B`等已知风险。检测到 `type: 小说章节` 或其他小说类型时，脚本只报告跳过原因。所有剧本命中必须标为“启发式命中”，回到上下文人工确认；不要按命中数自动改稿。

## 输出要求

- 先给一句话结论：最大优势、最大风险。
- 写清读取范围、资料状态和缺失项。
- 写清输入形态；小说输入不得伪造剧本扫描结果，重大首次兑现出现时列出里程碑与后续升级债务。
- 阻断项单列；无阻断也明确写出。
- 每个问题包含位置、证据、影响、置信度和最小修改级别。
- 核查模式不得偷偷附完整重写稿。
- 改写模式必须提供修改范围、改写稿和改写后复核。
- 需要用户复制使用的内容用代码块；真实本地文件使用可点击绝对路径。
