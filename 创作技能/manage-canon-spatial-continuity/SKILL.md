# 空间与时间连续性

维护人物在哪里、能否到达、何时到达，以及更改会影响什么。空间计算是正文背后的约束，不是角色应念出的参数表。

## 数据入口

使用者明确项目空间目录和正式文本目录。存在 `current.json` 时先按它加载当前全局/局部版本，不根据修改时间或最高版本号猜。注册表与文本来源都属于项目数据，不由技能默认定位个人文件。

仓库 `空间工具/` 的浏览器展示样例可辅助阅读地点和局部布局，但不包含完整来源/行程注册表。没有注册表时仍可按下面的人工流程做规划，未知项保留；不能宣称已跑注册表核验。完整格式见 [空间契约](references/spatial-contract.md)。

## 按变化量处理

同地点的措辞修订保留原空间绑定，不强制重建全图。新章、增加地点、改变出入口或层次、追逐、多人并行时：

1. 承接人物位置、装备、伤势和知识。先查既有地点 ID，不把内外图、昼夜图或新视角当新地点。
2. 只读相关全局条目、本章局部关系与最小相邻正文。源 hash 改变意味着回查差异，不代表自动改小说。
3. 逐级补齐实际需要的全城定位、交通连接、局部出入口及动作空间；上层关系够用就不重画。
4. 行程明确实际路线、升降绕行、交通方式、等待、换装、战斗及恢复。三维直线距离只是下界，不能等于行走距离。
5. 并行线使用同一叙事时钟，提前布防需交通与信息两条链都成立；不能让人物靠地图全知。
6. 核对当地上下、视线、遮挡与掩体区别、净空、高差、支撑、碰撞和撤离。未知能力写明，不用未来科技填缺口。
7. 正文从人物注意力成文，不强制报数；完稿只核对实际行动与交接是否符合规划。

## 版本与下游

地点 ID稳定，已被作品引用的版本冻结。另建修订快照，检查后原子更新当前指针。受影响章节、连接和派生文件标待复核，不能只改 hash 消除警报。

记录小说 hash、全局/局部版本与数据 hash，可放文本元数据或独立关联文件。接受某章不自动确认全城其他工作数值。剧本、导演与资产继承同一空间基准，不能各自发明出口、层高或时间。

导演关键移动说明起终点、实际路线、约距离与约用时，结合绕行、装备、重力、伤势及停稳动作；估算用范围。剪辑省略缩短画面，不缩短故事实际经过时间。

场景图或浏览器截图可以直接作布局参考，版本吻合就复用。图中文字和工程线帮助理解，不自动变成故事实体；成图偏差也不能反向改模型。已有设施编号按 [编号规则](references/facility-identifiers.md) 识别并跨视角复用，不替代几何测量。

## 只读检查器

在本技能目录运行：

```bash
python3 scripts/space_registry.py --registry /path/to/space/current.json audit --episode 31
python3 scripts/space_registry.py --registry /path/to/space/current.json impact --nodes S54 S55
```

`--registry` 必须显式给出，工具只读，不更新小说、设定或 hash。`audit` 可不限定章数用于确有必要的全局检查；候选全局比较用 `impact --candidate /path/to/global.json`。数据格式见空间契约，示例节点 ID 要换成自己项目实际值。

`ERROR` 表示结构/引用/时间矛盾，`STALE` 表示来源变化，`REVIEW` 表示覆盖或物理判断未完成。退出零只说明没有 ERROR/STALE，REVIEW 仍需阅读；不能将空行程或未验证路径报告为全城通过。影响查询只列已登记依赖。
