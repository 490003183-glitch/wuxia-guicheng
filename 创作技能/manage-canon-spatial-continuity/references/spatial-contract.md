# 空间与时间契约

## 三种尺度

**全城**：固定外观母图的身份与哈希，记录形态、空气与重力边界、坐标系和尺度的依据。雾峡轨城使用圆柱坐标 `a`（绕轴角度，度）、`r`（离转轴距离，公里）、`z`（沿转轴距离，公里）。当地向上通常是 r 减小，向下是 r 增大；z 不是楼层高度。数值属于工作比例时保持这个身份。

**连接网络**：每处地点使用稳定 ID，必要时记录父地点及内外接口。为实际通行建立有方向的连接，注明交通方式、实际路程、升降、开放条件；坐标相邻不等于道路相通。小空间尺寸不可随全城半径一起等比放大。异常内部、VR、匿名端和受保护的移动位置不参加普通欧氏地理推算；有入口时单独挂接入口。

**局部动作**：只为事件真正依赖的对象给尺寸与关系：入口/出口、可通行路、支撑面、掩体、视线、关键障碍。用当地切平面和当地上下解释人物姿势、水面及高差。货架遮视线不等于挡枪，观察缝不等于单向可见。门或封锁状态变化须同时解释人、机器人及飞行运载的不同通行条件。

## 时间与角色

- 叙事时间独立于成片时长。跨章只在明确连续时共用时钟；省略、切线、回忆不能机械累加。
- 旅程按实际连接排列；记录出发/到达区间，并计入叫援、准备、换装、等车、绕行、交战、受伤与休息。
- 多方行动用同一时间原点。提前布防需要交通与信息两条链都成立，空间图不给角色全知。
- 交通能力没有正式依据时可提出工作预算，写明假设及余量；不要把为了赶上会合所算出的平均速度反说成既有交通性能。
- 最短几何距离只能做下界排错，不含绕路与门禁。当前全局 `routeLegs.structureDistanceKm` 是旧版结构估算，不能用于速度或到达时间验证。
- 单靠两个半径的旋转重力差，不能推出明显的身体负荷变化；若规划另用人工调节解释，必须标成该层面的推演。复杂重力变化仍需回查正式设定及所选物理假设。

## 当前数据协议（schema_version: 1）

`current.json` 放在项目空间规划根目录，保存注册版本与这些文件引用。每个引用含相对根目录的 `path` 和文件字节 `sha256`：

- `global`：现行全局 JSON；保留已有 `version / geometry / scenes / episodes / sources / reference`。
- `locals[]`：每项有 `episode` 和 `data` 文件引用；局部数据的 `globalVersion` 必须匹配当前全局。原局部 `legs` 与 `timing` 为兼容导入，新增机器可检验行程放在 contracts。
- `rules`：当前基准中用户明确、正式来源与推演数值的边界说明。
- `contracts`：下述连接与行程。
- `provenance`：来源分组和小说关联；JSON 内包含 `sources[]`、`bindings[]`。

来源项保存 `path / sha256 / role / episodes`。`role` 可为 `canon`、`index`、`historical_input`；共享设定的 episodes 为空数组，表示影响域待按差异确定。历史输入丢失只影响追溯，不把已被替换的小说当当前正文。小说关联项保存 `episode / novel{path,sha256,version,status} / global_version / global_sha256 / local_version / local_sha256 / scene_ids`。路径可以绝对，也可相对注册根目录；不要复制小说到空间目录另立正文。

`contracts` 保存：

- `global_version` 与 `status`；推演不变成正式。
- `edges[]`：`id / from / to / length_m / mode / status`，可选 `speed_ceiling_mps`（有依据才填）。有方向；反向可通行应另记或明确扩展协议。无连接不等于永远不能走，而是不能据此声称已核实。
- `journeys[]`：`id / episode / actors[] / clock / steps[]`；每步有 `edge_id / start_min / end_min`，可选 `stationary_seconds`。时段可同时包含移动与事件，需说明其含义；脚本只计算剩余移动窗口的最低平均速度。
- `coverage[]`：`episode / scope / status / limitation`，主动暴露仅有历史地点序列、未展开交通模式或局部微动作的范围。

新人物行程用相同 actor 名和 clock 才能检查跨行程重叠；正好接续不算重叠。没有精确时间、路径或交通能力时，保留未知与人工核对，不填 0 装作完成。

## 检查与失效处理

`audit` 检查引用字节哈希、全局/局部/小说版本一致、地点 ID 唯一及引用存在、普通地点坐标范围、局部与全局坐标一致、有向行程连接、实际路程不小于三维直线下界、时间区间和同一人物同一时钟重叠。交通速度只对声明的上限检查；未声明则返回所需平均速度供人工判断。

`--episode` 限定来源和正文哈希检查到本章、最小相邻章及共享设定，结构检查保持全局 ID 完整性。未来章节尚未入表时返回缺少本章规划；不要把空结果当通过。

`impact --nodes ...` 列出引用地点的章节和小说关联；`--candidate` 对照新旧坐标、地点属性、全城几何和分章路线，报告变化及受影响章节。它列的是复核范围，不会替用户修改正式源。连接或局部动作变动尚未进入候选全局 JSON 时，直接传对应端点 ID。

工具不证明：空气/重力工程成立、所有旧章确有相通道路、视线不会穿墙、人体动作可完成、小说把时间写对了、角色有相应知识。这些按本次事件人工核对一次；结果及未解问题写在工作规划，不给正文加审计台词。
