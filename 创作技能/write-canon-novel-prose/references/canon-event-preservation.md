# Canon Event Preservation

Use this gate before adapting, compressing, re-ending, or rewriting confirmed source material. Its purpose is to preserve what happens independently from how the source presents it.

## 1. Build a source-event ledger

List every confirmed event relevant to the authorized passage before drafting. Record:

- who does what;
- when and where it happens;
- why it happens when causality is confirmed;
- the immediate result;
- what each character and the reader know afterward;
- how certain the source makes the event;
- which source carrier makes it legible.

Protected events include actions, decisions, outcomes, relationship events, knowledge transfers, promises, injuries, acquisitions, losses, and state changes. A single line, sound, shot, stage direction, prop, physical aftermath, or implication can carry a confirmed event.

## 2. Separate event from carrier

The carrier is the production or prose form: camera placement, sound cue, blocking, line of dialogue, image, cut, euphemism, or explicit narration. The event is what canon says happened.

A novel adaptation may replace a screenplay-only carrier. It may move information from a shot or sound into action, aftermath, memory, or implication. It may not silently remove the event together with the carrier.

When the user says `别这么尬`, `压缩`, `换个结尾`, or otherwise rejects a carrier, interpret that as permission to change the carrier only. Do not infer permission to delete, move, merge, weaken, or reverse the underlying event.

## 3. Produce the adaptation delta

Compare the source-event ledger with the proposed draft and list every event-level change:

- deletion;
- merge with another event;
- move in time or place;
- participant change;
- cause or outcome change;
- character-knowledge or information-permission change;
- change between on-page and off-page occurrence;
- certainty downgrade or upgrade;
- replacement with a general relationship fact that no longer confirms the specific event.

The last case is not preservation. If the source confirms that a character delivered an object that night, saying only that they delivered objects on earlier occasions changes both time and certainty.

## 4. Require informed authorization

For each non-empty delta, show the user three things before drafting or saveback:

1. original confirmed event;
2. proposed handling;
3. effect on canon, timing, causality, character knowledge, relationship state, or reader certainty.

Resolve the event-level change within the user’s existing explicit authorization; ask only when the proposed change is not covered. A general `可以`, `同意`, `执行`, or approval of a displayed sentence authorizes only the deltas already disclosed with those three parts. It does not retroactively authorize an undisclosed deletion or downgrade.

If the user approves style but the event delta was not disclosed, preserve the event and change only its carrier.

## 5. Block delivery and saveback when unresolved

Before delivery, compare the complete draft with the source-event ledger again. Before formal saveback, compare the staged body as well.

Proceed only when:

- the adaptation-delta list is empty; or
- every delta was separately disclosed and explicitly confirmed.

Stop and report the exact unresolved delta when the source is conflicting, the event cannot be identified confidently, or the rewrite would otherwise make a confirmed event less certain. Do not repair uncertainty by choosing the cleaner version.

## 6. Report the result

State which protected events were preserved through new carriers and which event-level changes the user authorized. Do not claim canon preservation merely because character names, relationship background, or broad plot direction remain intact.
