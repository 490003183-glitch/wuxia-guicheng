# 导演稿配图规划

把剧本全部视觉事实与导演必须保住的观看结果合并成最少完整资产集，不按镜头数派图。可以单独使用；配套 `wuxia-image-asset-prompts` 负责静态提示词和网页交付，也可由使用者自己的提示词流程接替。

## 输入与来源

使用用户指定的剧本、导演稿、正式资料 CANON_ROOT、资产目录 ASSET_ROOT 和输出目录 OUTPUT_ROOT。资产可用性通过使用者实际资产记录和文件核查，保留条件、结果、ID、状态与路径。不存在资产库时可使用已确认清单，未核查条目标待核查。相似图不能冒充精确匹配。

剧本拥有事件、信息权限和物品状态；导演拥有观看重点、优先级和生成组织；正式设定拥有外观事实；资产记录拥有图片是否存在与可用。冲突仅阻塞受影响条目，其他工作继续。

## 阶段与契约

- 导演前：读 [基础规划](references/pre-director-baseline.md)。只依剧本列 BASE 需求，不虚构导演引用、哈希或 P0/P1；Markdown 清单即可。
- 导演后：完整读取当前剧本和导演稿，再读 [决策规则](references/decision-contract.md) 与 [JSON 契约](references/plan-schema.md)。新计划使用 director-asset-plan/v2。

导演后记录两份源文件的实际绝对路径、状态、字节数、mtime、SHA-256；导演绑定的剧本哈希须相同。小说改编剧本还要确认小说来源没有过期。来源改变时标待同步，重审受影响决策，不只替换哈希。

## 规划流程

1. 枚举地点、可见角色身份和服装、关键道具装备、车辆生物、界面、空间连接、持续损伤与结果。给每项 baseline_ref，每项须有决策，不因导演没强调就遗漏。
2. 列全部 P0/P1 引用及受保护结果，保留原 SH/ED/TAKE 标识。每项映射到决策，包括明确的 NO_ASSET。
3. 持续灯光、烟雾、水位、开闭和损坏跨单元延续时，记录初态、触发事件、末态和引用。空间相同而光源不同不算精确复用。需要独立参考的状态绑定 REUSE 或 CREATE。
4. 图片须确实锁身份、结构、状态、拓扑、尺度、遮挡或关键结果，并减少具体生成错误。一个母版可服务多个镜头；节奏、表演、镜头运动、声画转场和剪辑顺序不自动成为图片。
5. 逐项分类：REUSE 精确复用；CREATE 确有缺图；TEXT_ONLY 短文字足够；NO_ASSET 属其他制作层；BLOCKED 缺事实或设计依据。只有未解决 CREATE 进入提示词队列。
6. 合并兼容需求，细节在整合母版之前，母版在派生之前；依赖无环。尚未触发保底的额外图片只列条件备选。
7. 有同版 3D 规划截图时直接复用，核对版本、出口、通道、遮挡与路线；不从透视图猜精确尺寸，不另造空间数据。
8. 每个非阻塞 P0 给出保留同一事实的保底，不把已发生接触、越界、毁损或到达删成含糊反应。

## 交付和验证

交付 JSON 与可读决策表，覆盖来源、基线、P0/P1、持续状态、缺图顺序、派发队列和阻塞。需要提示词时继续处理 CREATE；生成与正式入库按当前授权执行。

Node.js 18 或更新版本，仅标准库。相对于本技能目录运行：

```bash
node scripts/validate_director_asset_plan.mjs /absolute/project/asset-plan.json
node scripts/run_plan_tests.mjs
```

校验器默认核对源文件内容、路径、图片存在性、状态绑定、依赖和覆盖。图片存在不证明语义吻合，须看图核对；路径使用当前操作系统绝对路径。

planning 表示尚有缺口；ready_for_user_confirmation 表示所有图片和使用绑定已核实；confirmed_complete 表示具体图谱已获用户确认。已经确认同一图谱时保留证据，不重复询问；校验器不能自行推断确认。

交接只含实际上传的最终参考，记录需求 ID、资产 ID、路径、使用范围、上传次序、锁定和不继承事项，重复源哈希和状态绑定。只用于制作母版的上游细节不自动加入下游上传。
